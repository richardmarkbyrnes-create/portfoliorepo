The through-line

Systems, not screens.

  • SAP · Fiori Tools — built and maintained a 200-component Figma library that had to retheme across ten-plus VS Code themes, with tokens mapped to production CSS and JSON.
  • Cashbook — rebuilt a navigation architecture so new product modules could be switched on without redesigning the shell.
  • Miro · Insights — designed an adaptive card component that has to hold up in every structure a team invents on an open canvas.

How I work

Close to the users, close to the engineers.

  • Start with the mess — the interesting problems are usually in the workflow around the product, not inside it.
  • Build to think — I design in the browser. This deck and my portfolio are hand-written HTML, CSS and JavaScript, no framework.
  • Stay through the build — a design isn’t done when it’s handed over. I’d rather be in the pull request than in the review.
  • Trust is a design problem — with AI features especially, showing the source beats sounding confident.

Why this role

Complex domain, expert users, one coherent product.

  • Data-dense surfaces are the work I know — ledgers, IDEs, thousands of customer calls. Finding the few things that matter and making them impossible to miss.
  • Owning a system, not policing one — I’ve held a library at 200 components and know when consistent beats perfectly systematic.
  • A domain I’d have to earn — I don’t know protein engineering. I do know how to sit with an expert until their workflow makes sense.
